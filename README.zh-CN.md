# anSMBwinRedirector

一个小巧的 Windows 工具：做**透明的 TCP 目的端口改写**，让 Windows 自带的 SMB 客户端 / 资源管理器
能够访问运行在 Android 上、监听**非特权端口**（默认 `4450`，可配置）的 `anSMBserver` 实例。

```text
Windows 资源管理器 / 自带 SMB 客户端
        │  TCP: <临时端口> → AndroidIP:445
        ▼
anSMBwinRedirector
        │  透明改写【目的端口】：AndroidIP:445 → AndroidIP:<Android SMB 端口>
        ▼
Android 上的 anSMBserver（真正监听的是那个可配置端口）
        │  TCP: AndroidIP:<端口> → Windows 临时端口
        ▼
anSMBwinRedirector
        │  透明还原【源端口】：<端口> → 445
        ▼
Windows 资源管理器 / 自带 SMB 客户端
```

**为什么需要它**：Android 应用无法绑定 1024 以下的特权端口，所以 `anSMBserver` **不能**监听 `445`；
而 Windows 自带 SMB 客户端**只认 `445`**，UNC 路径也没法指定端口。（注意因果方向：`anSMBserver` 使用
非标准端口是 **Android 平台限制**的结果，**不是**为了避开 Windows 自身 `445` 的冲突。）

**一句话概括它的行为** —— 对每个目标，程序只做一件事：把**目的端口** `445` 改成你配置的端口
（**目的 IP 不变**、**Windows 源端口不动**），反向再把源端口还原。它**不是**"本地 445 → 4450 的端口转发"，
**也不是**通用的 `FROM → TO` NAT，`netsh interface portproxy` 之类的工具**无法**替代它。
它既不是 SMB 服务端、也不是 SMB 客户端，且不处理 UDP。

## 1. 运行要求与安装

| 项 | 要求 |
| --- | --- |
| 系统 | **仅 Windows x64 (amd64)** —— 其它都不支持 |
| 权限 | **管理员**（加载 WinDivert 驱动需要） |
| 同目录文件 | **`WinDivert.dll` 与 `WinDivert64.sys` 必须与 exe 同目录**；两者缺一不可（见 §6） |
| 目录 | **exe 所在目录必须可写**（配置、它的备份与临时文件都写在这里 —— 见 §4） |
| 网络 | 能访问目标 Android 设备的 IP |
| Android 端 | 需你**自行**在设备上运行 `anSMBserver` 并确认其监听端口；本项目**不包含、也不提供**它 |

> ⛔ **不支持 Windows on ARM64**：amd64 程序也许能在模拟下运行，但内核驱动必须是 ARM64，
> 随包分发的 amd64 `WinDivert64.sys` 无法加载。程序会在做任何其它事情之前**拒绝启动**并给出明确说明。
> ⛔ 不支持 32 位 Windows（amd64 可执行文件无法启动）。

**解压即用 —— 没有安装程序。** 把发布包解压到**任意可写目录**：

```text
anSMBwinRedirector-<版本>-win-x64/
├── anSMBwinRedirector.exe
├── WinDivert.dll            ← 第三方（WinDivert 2.2.2-A）；必须与 exe 同目录
├── WinDivert64.sys          ← 第三方；必须与 exe 同目录
├── language.json            ← 界面文案（`en` + `zh-CN`；UTF-8）
├── LICENSE                  ← 本项目的 GPLv3 全文
├── THIRD_PARTY_NOTICES.md   ← 第三方组件及其许可全文
└── README.md                ← 面向使用者的说明（英文）
```

- 发布包**恰好这 7 个文件**，且**不含 `config.json`**（那是运行期数据，首次点「应用更改」时才产生 —— 见 §4）。
- 中文说明 `README.zh-CN.md` **只在源码仓库中提供**，**不随发布包分发**（发布包固定为上述 7 个文件）。
- ⚠️ **不要放在你不可写的目录**（例如默认权限下的 `C:\Program Files\...`）：首次保存会失败，
  程序会把"配置目录不可写"判为**配置不可用**（§4.3）。
- 该目录是**自包含**的：整体移动或改名后，配置与 WinDivert 文件一起走（§4.1）。

### 1.1 它会动到你系统上的什么

"自包含"说的是**磁盘上的文件**：程序**不会在自身目录之外写任何文件**，也**从不写 `%PROGRAMDATA%`**。
但它**不是**无副作用的 —— 它会使用 Windows 的系统设施，这和"把文件写到别处"是两件不同的事。

| 动作 | 会动到程序目录之外的什么 |
| --- | --- |
| 对**配置了用户名/密码**的目标点「连接」 | 在该 IP 的 **Windows 凭据管理器**里创建/覆盖一条凭据（`cmdkey`）。若已存在，会**先询问**再覆盖 |
| 「启动」/「停止」/「退出」 | 通过**服务控制管理器**安装、停止或删除 **`WinDivert` 服务**（见 §6.1）。那是系统级服务注册，不是某个目录里的文件 |
| 调试 → **重启 Workstation** | 停止并启动 **`LanmanWorkstation`** 服务（见 §6.2） |
| 「连接」（打开共享） | 让**系统默认处理程序**（通常是资源管理器）打开 `\\<Android IP>\` |

## 2. 快速开始

1. 把发布包解压到**可写目录**。
2. 右键 `anSMBwinRedirector.exe` → **以管理员身份运行**。
3. 点「**添加**」，填 **Android IP** 与 `anSMBserver` **实际监听**的 **Android SMB 端口**（默认 `4450`）。
4. 点「**应用更改**」，再点「**启动**」。
5. 选中该行，点「**连接**」（或右键该行 → 连接）。

**「启动」和「连接」是两件事** —— 这里最容易误解：

| | 作用 |
| --- | --- |
| **启动** | 启动**重定向引擎**，让所有目标的规则生效 |
| **连接** | 对**选中的那一个目标**：写入它的 Windows 凭据（若配置了），然后请 Windows 打开 `\\<Android IP>\`。它**不是**独立的网络探测，且**要求该目标已经保存且正在运行** —— 它**不会**替你启动重定向 |

之后就可以像平常一样在资源管理器里浏览 `\\<Android IP>\<共享名>`。Windows 用的仍是 `445`，
程序在背后把它改写成 `<Android IP>:<你配置的端口>`。

程序**不修改系统代理**，也**不使用** `netsh portproxy`。

## 3. 首次运行（详细）

下面的步骤描述的是：机器上**还没有配置文件**时的行为。

1. 右键 `anSMBwinRedirector.exe` → **以管理员身份运行**。
2. 主窗口出现（同时有托盘图标）。**此时还不会创建配置文件** —— 首次启动是空配置；
   `config.json` 只在你首次点「应用更改」时才出现在 **exe 所在目录**。
3. 点「添加」并填写目标：
   - **Android IP**：设备 IPv4 地址（例如 `192.168.1.100`）；
   - **Android SMB 端口**：`anSMBserver` 实际监听的端口（默认 `4450`，可配置）；
   - **用户名 / 密码**（可选）：填了的话，连接前会写入 Windows 凭据存储（`cmdkey`）；
     留空则不动系统里已有的凭据。*用户名与密码要么都填，要么都留空。*
   - *一个 Android IP 只能有一条规则。*
4. 点「应用更改」→ `config.json` 创建于 **exe 同目录**。⚠️ **首次**保存**不会**产生
   `config.json.bak` —— 还没有上一版可备份（见 §4.2）。
5. 点「启动」。
6. 要打开该服务器的共享：**选中该行并点「连接」**（或右键该行 → 连接）。
   该目标必须**已保存**（应用更改）且**正在运行**（启动）。

## 4. 配置文件

### 4.1 位置与格式

```text
<anSMBwinRedirector.exe 所在目录>\config.json
```

- 备份与临时文件在**同一目录**：`config.json.bak` 与 `config.json.tmp`。
- **首次启动不会创建该文件**：它只在你首次「应用更改」时出现。
- 保存方式是"先写临时文件，再做一次文件替换"：程序**绝不先删除当前有效的 `config.json`**
  （⚠️ **不承诺**掉电/崩溃时的磁盘级原子性）。

```json
{
  "schema_version": 2,
  "targets": [
    {
      "id": "<稳定 UUID>",
      "android_ip": "192.168.1.100",
      "android_port": 4450,
      "username": "ansmb",
      "password": "……"
    }
  ]
}
```

- `id` 由程序生成且保持稳定；**`android_ip` 在规则集内必须唯一** —— 重复会被拒绝。
- 每条规则有四个可配置字段：**Android IP**、**Android SMB 端口**、**用户名**、**密码**
  （后两者可留空；要么都填、要么都空）。与之对应的 Windows 侧 **TCP 445 固定、不可配置**。
- `targets` 可以为空（表示"没有配置任何重定向目标"）。

### 4.2 `config.json.bak` 的行为

| 保存次数 | 结果 |
| --- | --- |
| **第一次**保存（还没有 `config.json`） | 只生成 `config.json`。⛔ **不产生 `.bak`** —— 此时没有上一版可备份 |
| **第二次及以后**保存 | 在替换之前，把**上一版** `config.json` 保留为 `config.json.bak` |

所以看到 `.bak` 就意味着"你至少保存过两次，它保存的是你上一次保存之前的那一版"。
它**不是**滚动历史 —— 任何时刻只有一个 `.bak`。

### 4.3 「配置不可用」

**总原则**：如果 **exe 同目录下**的配置不可用，程序拒绝假装自己有配置。进入该状态的条件是：

- 文件存在但**无法读取**、**无法解析**或**校验失败**（含重复 IP、非法字段、或由更高版本写入的
  `schema_version`）；**或**
- **配置目录不可写**（启动写探测失败 —— 见下）。

在「**配置不可用**」状态下，程序：

```text
- 不加载任何 Target；
- 不建立任何 runtime / 不打开 WinDivert handle；
- 禁止「启动」（也就无法进入"运行中"）；
- 禁止「应用更改」（防止覆盖可修复的原文件）；
- ⛔ 不会静默以空配置继续，也不会自行删除或改写任何文件；
- 界面显示：文件路径 + 失败原因，并提供两个**显式动作**（见下）。
```

**从该状态恢复 —— 两个显式动作**（显示在窗口顶部的横幅里）

| 动作 | 作用 |
| --- | --- |
| **复制配置路径** | 把 `config.json` 的**路径**放进剪贴板。⛔ 它**不会**打开文件或文件夹 —— 你需要**自己**用文本编辑器打开该路径来检查或修复 |
| **用空配置重新开始** | 以空配置重新开始，**且不删除任何东西**：它把不可用的 `config.json` **改名**为 `config.json.corrupt-<时间戳>`（内容完整保留），然后以空配置继续。会先弹确认框，取消则什么都不变。当文件是由更高版本的 `schema_version` 写入时，该按钮**仍然显示但处于禁用态**（防止误降级破坏数据）。改名本身仍要求目录可写 |

**启动时的写探测**：每次启动，程序会在配置目录（= exe 所在目录）里做一次**轻量写探测** ——
创建一个**专用且唯一**的探测文件（文件名前缀 `.ansmbwinredirector-write-probe-`），写入少量字节后**立即删除**。

- 探测**只清理本次创建的文件**；⛔ 不使用 `config.json` 这类用户文件名，因此**不会**留下空的 `config.json`。
- 探测失败（或探测文件**清理失败**）⇒ 进入「配置不可用」，并在原因里给出**目录路径 + 底层错误**。
- ⚠️ 两件不同的事：探测成功**不等于**保存一定成功（真正保存时仍会独立检查写入/备份/替换的每一步）；
  另外探测文件**不是**配置文件 —— 探测成功**绝不会**创建或修改 `config.json`。

**常见原因**

| 现象 | 处理 |
| --- | --- |
| `CONFIG_IO_ERROR`（目录不可写 / 权限不足） | 把程序目录改成可写（或换一个可写目录）；例如**不要**放在默认权限的 `C:\Program Files\` 下 |
| `CONFIG_IO_ERROR`（探测文件无法清理） | 检查是否有安全软件锁定该目录；这也按"不可写"处理 |
| `CONFIG_PARSE_ERROR` / `CONFIG_VALIDATION_FAILED` | 先点「复制配置路径」拿到路径，再**自己**用文本编辑器打开该路径、手工修复；界面会**列出全部**违规项 |
| `CONFIG_SCHEMA_UNSUPPORTED`（配置由更高版本写入） | 「用空配置重新开始」**保持禁用**，这是有意设计；请改用更高版本（防止误降级破坏） |

## 6. WinDivert：重要行为、修复与清理

重定向靠的是在网络层拦截并改写数据包，依赖第三方组件 **WinDivert 2.2.2-A**。

- 它由 **`WinDivert.dll` + `WinDivert64.sys`** 组成，**必须放在 `anSMBwinRedirector.exe` 同目录**。
- 启动时（以及每次「启动」）程序会校验这两个文件的 **SHA-256**：
  - **缺失** → `RUNTIME_FILE_MISSING`（带完整路径）；
  - **被修改** → `RUNTIME_FILE_CORRUPT`（同时给出**实际**与**期望**的 SHA-256）。
  - ⛔ 两种情况程序都**只报告**：绝不覆盖、绝不重新下载、绝不删除你的文件。
- 首次「启动」时，WinDivert 驱动会被**按需安装并加载**（会创建 Windows 服务，需要管理员权限）。
  安装/加载由 WinDivert 自己完成；**"接管"（停止并删除已存在的服务）由本程序完成** —— 见 §6.1。

### 6.1 WinDivert 服务由本程序负责（启动 / 停止 / 退出）

> ⚠️ **可能影响其他使用 WinDivert 的软件**
>
> 「启动」会**接管系统中名为 `WinDivert` 的服务**：如果它已经存在（由别的工具创建），程序会先**停止并删除**它，
> 再从本程序目录安装驱动。**如果其他软件也依赖该服务，它们的运行可能受到影响。**
> 程序**无法枚举**系统中所有 WinDivert 使用者（见 §6.2 末尾），因此**不能保证**接管操作不会影响其他软件。
> 建议在启动前**关闭**可能使用 WinDivert 的其他工具。

**「启动」时（接管）**：如果 `WinDivert` 服务**已经存在**（由别的工具创建，或系统中遗留的），程序会先**停止并删除**它，
等它确实消失（`sc query` 返回 **1060**）之后，才让 WinDivert 从**本程序自己的目录**安装 `WinDivert64.sys`，
并核对服务的实际 `ImagePath` 是否指向本目录。

> ⛔ 程序**从不复用**已存在的 WinDivert 服务 —— 实测表明复用会继续从**服务原来的路径**加载 `.sys`。
> 接管失败会报明确错误（`WINDIVERT_TAKEOVER_FAILED`），且**绝不**回退到旧服务。

| 动作 | 对 WinDivert **服务**的影响 | 对 `WinDivert.dll` / `WinDivert64.sys` **文件**的影响 |
| --- | --- | --- |
| **启动** | 若已存在 ⇒ 停止并**删除**，然后从本程序目录安装 | **不**修改（只在缺失/被改动时报告） |
| **停止** | 停止并**删除**服务（`sc query` 回到 1060），然后等 `.sys` 不再被占用 | **不**删除 |
| **退出** | 实测：若当时在运行，退出后 `sc query WinDivert` 为 **1060（未安装）** | **不**删除 |
| **系统重启** | ⛔ **不会**删除服务注册 | ⛔ **不会**删除那两个文件 |

> ⚠️ **不得把"重启"等同于"清理"**：重启只让**当前加载的驱动实例**随系统关机一起消失
> （所以它能解决驱动版本冲突），既**不会**删除服务注册，也**不会**删除那两个文件
> （它们只是你解压出来的普通文件）。

⛔ 程序**没有**"强制清理 / 绕过接管"的卸载入口，也**绝不删除**你的 `WinDivert.dll` / `WinDivert64.sys`。
如果你想清理别处留下的服务注册，请按 WinDivert 官方说明自行处理（那不是本程序的功能）。

### 6.2 「调试」窗口

「调试」按钮打开一个**诊断**窗口，分三部分：

1. **只读诊断**（什么都不修改）：程序目录；`WinDivert.dll` / `WinDivert64.sys` 的路径、**文件版本**
   与**实际/期望 SHA-256**；WinDivert 服务是否存在、当前状态、`ImagePath` 是否指向本程序目录；
   **运行期驱动版本**（只读诊断**不打开驱动 handle**，所以此项显示"尚未检查"）。
2. **`修复 / 重新接管 WinDivert`**：通过与 §6.1 **相同的接管流程**移除已存在的服务注册，
   并重新核对本程序目录下的两个运行文件。**它不加载驱动**（驱动仍由下一次「启动」加载），
   ⛔ 不修改任何文件。重定向运行期间该按钮不可用（先「停止」）。
3. **`重启 Windows Workstation 服务`**：用途是**清掉 Windows SMB 客户端的会话状态**。
   ⛔ 它**不是**"网络修复"，也**不保证**能修好（实测）。会先弹确认，并会打断已有的 SMB 连接。

> ⚠️ 诚实声明：`REFLECT` 层上的 WinDivert 使用者**无法被枚举**，所以程序**无法证明**
> 系统上不存在别的 WinDivert 使用者。

## 7. 故障处理（常见问题）

| 现象 | 可能原因 / 处理 |
| --- | --- |
| 启动时报 `RUNTIME_FILE_MISSING` / `RUNTIME_FILE_CORRUPT` | 同目录的 `WinDivert.dll` / `WinDivert64.sys` 缺失或被改动：把正确的文件放回去（程序**绝不**下载或覆盖它们） |
| 报"无法接管系统 WinDivert 服务"（`WINDIVERT_TAKEOVER_FAILED`） | 服务无法停止/删除（可能被其它程序占用）：稍后重试，或重启后重试 |
| 状态栏显示「配置不可用」 | 见 §4.3：修复配置文件，或让目录可写；在那之前程序不会启动重定向，也不会覆盖该文件 |
| 「连接」**长时间没有反馈** | 目标地址不可达时，Windows 打开 `\\<IP>\` 可能很久才返回（实测 >3 分钟）。这是**系统行为**，不是本程序给出的判定；期间按钮保持禁用 |
| 「连接」被拒并提示"重定向未运行" | 「连接」不会替你启动任何东西：先点「启动」（§2） |
| 资源管理器要求输入用户名/密码 | 该目标没有配置凭据；在「编辑」里填用户名/密码，点「应用更改」，再用「连接」把它们写进 Windows 凭据管理器 |
| 想彻底清理 WinDivert 残留 | 见 §6.1：程序不提供强制清理入口；请按 WinDivert 官方说明处理 |

## 8. 已知限制与安全说明（v1.0）

**已知限制**

- **仅 Windows x64**；不支持 32 位，也不支持 ARM64（ARM64 会被明确拒绝）。
- **exe 所在目录必须可写**：配置与其备份都写在那里（§4）。
- ⛔ **没有**"强制清理 / 绕过接管"的 WinDivert 卸载入口（§6.1）。
- **没有**安装程序、**没有**自动更新、**没有**代码签名。
- `config.json` 里的**未知字段会被拒绝**（而不是忽略）；更高版本的 `schema_version` 会让配置不可用，
  这是有意设计（§4.3）。
- 它既不是 SMB 服务端也不是 SMB 客户端，不是通用端口转发/代理，且不支持 UDP。
- ⚠️ 目标地址**不可达**时，「连接」可能**长时间（实测 >3 分钟）没有结果** —— 这是 Windows 打开 `\\<IP>\` 的行为。
- ⛔ 对配置写入在极端情况（掉电、崩溃）下**不承诺**磁盘级原子性 —— §4.1。

**安全：密码以明文存储**

> ⚠️ **v1.0 中 `config.json` 里的密码是明文存储的。**
> 程序**不宣称**安全存储 —— 它既不加密该文件，也不把配置本身放进 Windows 凭据管理器。
> 该文件与 exe 同目录，继承该目录的访问控制；请你自行保护好目录与磁盘。
> ⛔ v1.0 **不提供**任何加密存储密码的选项。

**目录里所有可能含密码的文件**

| 文件 | 是否含明文密码 |
| --- | --- |
| `config.json` | **是** |
| `config.json.bak`（从第二次保存起 —— §4.2） | **是**（它是上一版配置的副本） |
| `config.json.tmp` | 正常保存时只在极短时间内存在；若保存被**异常中断**（掉电、崩溃、强制结束进程）则**可能残留**。它与 `config.json` 一样含明文密码 |
| `config.json.corrupt-<时间戳>`（由「用空配置重新开始」产生 —— §4.3） | **是**（它就是被保留下来的那份配置，内容未改动） |
| `config.json.migrated-<时间戳>`（若目录中存在） | **是**（它是一份配置副本，含其中的明文密码） |

⚠️ 如果目录里还有**你无法确认来源**的 `config.json*` 文件（例如带时间戳后缀的副本），
请**同样**按含密码的材料处理。

⚠️ **由此带来的后果**：当你**移动、拷贝、分享、备份或删除**程序目录时，要把这些文件当作
**凭据材料**看待，而不是普通文本。只删 `config.json` 会把你的密码留在其它文件里。

（「连接」写入的 Windows 凭据由**系统凭据管理器**保存，与这些文件无关。
⛔ 密码**绝不**出现在日志、诊断详情、调试窗口、错误信息或窗口标题里。）

## 10. 从源码构建

需要 **Go 1.27.1**（见 `src/go.mod`），可在任意能交叉编译到 Windows 的平台上构建。

```sh
scripts/build-release.sh 1.0          # 产物在 dist/release/
```

要点：

- 发布包**恰好 7 个文件**（见 §1）；`dist/` 已被 `.gitignore` 忽略。
- **Manifest 是必需的**：GUI 框架 `lxn/walk` 需要 Common-Controls v6 清单，缺失会导致窗口**完全建不出来**。
  清单以 `.syso` 资源形式**内嵌**（`cmd/ansmbwinredirector/rsrc_amd64.syso`），
  该文件由 `go tool rsrc`（版本锁在 `go.mod` 的 `tool` 指令里）**可复现地**重新生成；
  构建脚本会重新生成并与其**逐字节比对**，不一致直接失败。
- **WinDivert 的 SHA-256 固化为编译期常量**（`src/internal/winvert/assets_common.go`）。
  升级 WinDivert 时必须同步更新这些常量 —— `go test ./internal/winvert` 会强制这一点。
- ⚠️ 本程序**不是**可跨构建逐字节复现的：构建脚本会把**构建时间**注入 exe 的版本信息，
  因此每次构建 exe 的哈希都不同（其余 6 个文件是仓库内容的逐字节副本）。
  要核对某个 exe 来自哪次提交，请看**内嵌的 `vcs.revision` / `vcs.modified` 与版本字符串**。
